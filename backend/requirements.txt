# The 33 shared floors live in `requirements-base.txt` and are included below,
# so `environment.yml` can include the same file instead of restating them
# (issue #1522). Everything spelled out in *this* file is here because the
# CPU-only torch wheel must not reach local dev.
#
# `backend/Dockerfile` COPYs both files; pip resolves `-r` relative to the
# including file, so the include works from the image root and from `backend/`.
-r requirements-base.txt

# Semantic retrieval — MiniLM embeddings for paper_rag.py (issue #874).
# CPU-only torch wheel: the extra-index-url below resolves torch to the
# lightweight CPU variant (~250 MB) rather than the CUDA build (~2.5 GB).
# sentence-transformers brings torch transitively; pinning torch here forces
# the CPU wheel so the Docker image stays within budget.
#
# This block is deliberately NOT in requirements-base.txt: environment.yml
# includes that file, and the extra-index-url would drag the CPU wheel onto
# dev machines and lose MPS on Apple Silicon. environment.yml therefore keeps
# its own native-wheel torch / sentence-transformers floors, and
# backend/tests/test_env_requirements_alignment.py holds the two in lockstep —
# they are the only floors still written down twice.
--extra-index-url https://download.pytorch.org/whl/cpu
torch>=2.13.0,<3.0  # CPU-only wheel via pytorch whl index (see extra-index-url above); no +cpu here, pip rejects a local version label on a >= specifier
sentence-transformers>=6.0.1  # all-MiniLM-L6-v2 semantic retrieval; baked at Docker build time
